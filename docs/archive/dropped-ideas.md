# 已放弃的想法

> 这里归档讨论过、但决定不做的想法，以及放弃的原因。用户没有明确要求时，不要把这些功能加回来。
>
> 标为「暂不做」的项，用户原话带有「目前」「暂」，以后可能重新考虑。要重新考虑时，先移到 [backlog.md](../backlog.md)。

## 原始构想：氛围编程记事本

项目最早的构想是「一个跟着实际工作目录走的氛围编程记事本」。核心是记录当前要做的事项和项目记忆，编排即将发送的会话，并决定是否分线程。拓展能力有：网页元素识别、AI 辅助表达、项目上下文与资源管理器、窗口检测和互达、实时预览编辑、预制提示词管理。

2026-11-07 讨论后，产品收窄为现在的 Vibe Atlas：由人手动记录、手动发送、手动打勾的项目管理中枢。原构想中保留下来的只有两项：

- 记录要做的事项：变成了项目 → 模块 → 改进点；
- 实时预览编辑：变成了 Markdown 即时预览编辑。

## 放弃清单

| 想法 | 结论 | 原因 |
|---|---|---|
| 内置 AI：需求拆分、提示词改写、AI 面板、专门的 AI Agent 窗口 | 不做 | 用户决定不考虑 AI，由人主动发送 |
| 把项目文件上下文提供给 AI，辅助规划会话 | 不做 | 同上 |
| 网页元素识别（浏览器扩展：点选页面元素加入输入） | 不做 | 别人的项目已经有，没必要做在这里 |
| 项目记忆 | 不做 | 记忆可以靠外部（AGENTS.md 或其他记忆工具） |
| 项目文件树 / 资源管理器 | 不做 | 和 AI 上下文一起放弃，编辑器自带的就够用 |
| 识别当前编辑器窗口，自动跟随当前项目 | 暂不做 | 用户：目前让人手动切换 |
| 识别正在交互的 AI 工具，自动标记会话是否完成 | 不做 | 状态由人自己打勾 |
| agent 集成：Claude Code hooks、MCP server、CLI | 暂不做 | 用户：agent 暂不考虑。例外（用户 2026-11-08 明确要求）：只读本机的 Claude Code / Codex / codeg 会话供「选择会话」，以及点开 Claude Code 会话链接时运行一次 `claude --desktop --resume`，见 [本机会话计划](../../plans/2026-11-08-local-sessions/00-overview.md) |
| 会话编排、分线程、git worktree 管理 | 不做 | 一次只发一条，由人决定 |
| 定时给特定应用发送提示词 | 不做 | 由人主动发送 |
| 完整的预制提示词管理：标签、变量、给 AI 读、定时发送 | 不做 | 和 AI、自动发送绑在一起。轻量的「提示词片段」作为候选留在 backlog |
| 云同步、账号、多设备 | 不做 | 一个人在一台电脑上开发，不需要 |
| 多人协作：成员、权限、Cycle、估点 | 不做 | 这是 Linear 变重的原因 |
| 「进行中只能有一条」的限制 | 不做 | 是对用户的误解，用户没有这样要求。「一次只发一个」只是使用习惯，不是规则 |
| 移动端 | 不做 | 只服务电脑上的开发 |
