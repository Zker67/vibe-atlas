# 第 1 步：技术验证

> 状态：`[partial]`：已实现，我能自验的检查已通过，等待用户验收。实施情况见 [09-implementation-report.md](./09-implementation-report.md)。

## 目标

用最小代码验证 [tech-stack.md](../../docs/architecture/tech-stack.md) 里还没验证的几项，决定是否沿用推荐的技术组合。这一步的代码可以丢弃，不追求结构。

## 当前已知（2026-11-07）

- MyGo 文档要求 Go 1.27 以上，带 Web 前端的项目还需要 Bun；Windows 11 自带所需的 WebView2。
- 本机已有 Go 1.27.3、Bun 1.4.4、Node 26；MyGo CLI 还没装，可以通过 `go run` 或 `go install` 使用。
- MyGo 文档里有「面板」窗口：浮在所有应用（包括全屏应用）上方，能接收键盘输入，适合做快速记录小窗。

## 要验证的事

| 项目 | 怎么算通过 |
|---|---|
| 快速记录小窗速度 | 程序已经在托盘运行时，按快捷键到可以打字，主观上没有等待。实测并记录耗时，作为之后的基准 |
| 小窗焦点 | 在 VS Code、浏览器、终端上方弹出时都能直接打字；按 Esc 后焦点回到原来的应用 |
| 中文输入 | 在小窗和 Markdown 编辑器里用中文输入法输入，候选框位置正确，不丢字、不重复上屏 |
| Markdown 即时预览 | 能做出「光标所在处显示源码、其他地方显示渲染效果」的最简版本 |
| SQLite | 打包后的程序能读写数据库，重启后数据还在 |
| 打开链接 | `https:`、`vscode:`、`file:` 三种链接都能交给系统默认程序打开 |
| 托盘与单实例 | 关掉主窗口后程序留在托盘；再次启动时只显示已有的窗口 |
| 打包 | 打包出的程序在没有开发工具的情况下也能运行 |
| 资源占用 | 记录打包体积和常驻内存，作为之后的基准 |

## 失败时怎么办

| 情况 | 备选方案 |
|---|---|
| 小窗太慢或焦点不对 | 只把小窗改用 MyGo 原生 UI，主窗口不变 |
| MyGo 缺少关键能力，或问题无法绕过 | 改用 Electron，重做这一步的验证 |
| Markdown 即时预览在 WebView2 里中文输入有问题 | 先查编辑器的已知问题和设置；仍不行就换编辑器方案 |
| SQLite 驱动打包失败 | 换其他 Go SQLite 驱动，并评估对以后 macOS 打包的影响 |

换路线前先告诉用户原因和影响，用户同意后再继续。
