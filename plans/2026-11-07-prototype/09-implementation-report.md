## 「做的时候再定」的决定

| 步骤 | 问题 | 决定 |
|---|---|---|
| 1 | 验证代码是否保留 | 没有写一次性的验证程序，直接在正式项目上做，用打包后冒烟测试代替能自动化的验证项 |
| 1 | 默认快捷键 | `Ctrl+Alt+Space`（`Alt+Space` 是 Windows 的窗口菜单） |
| 2 | 源码目录 | 以 MyGo 模板为基础：Go 端在根目录，数据层在 `internal/store/`，前端在 `src/` |
| 2 | 设置存在哪里 | 存在同一个 SQLite 的 `settings` 表 |
| 2 | 左右栏能否拖动 | 侧栏固定宽度；队列和详情之间可以拖动，宽度会记住 |
| 3 | 新建和改名 | 小对话框，错误就地显示在输入框下面 |
| 3 | 模块放在哪里 | 左侧项目列表下面 |
| 4 | 详情区位置 | 队列右边 |
| 4 | 快捷键 | 见 [product.md](../../docs/product.md#改进点与队列)，设置里也有一览 |
| 4 | 能否跨三块拖动改状态 | 不能；只在待办里拖动排序，状态用按钮、右键菜单和快捷键改 |
| 5 | 源码显示范围 | 光标所在的行显示源码；编辑器失焦后整篇渲染 |
| 5 | 代码块高亮的语言 | 用 `@codemirror/language-data`，常见语言都支持，用到时才加载 |
| 6 | 小窗大小和位置 | 620×340，出现在鼠标所在屏幕的水平中间、上方四分之一处 |
| 6 | 切换项目、类型、模块的键 | `↑ ↓` 项目、`Tab` 类型、`Ctrl+↑ ↓` 模块 |
| 7 | 图形 | 只用进度条和数字 |
| 7 | 完成历史很长时 | 每次多显示 100 条 |
| 8 | 安装包还是免安装版 | 两个都有：MyGo 构建时同时生成 |

## 和计划不一样的地方

- 第 1 步没有单独做「一次性验证程序」，验证项分成两类：能自动化的放进冒烟测试和数据层测试；速度、焦点、中文输入、链接打开等需要人感受的，并入用户验收。
- 第 3、4 步计划里「先用普通输入框占位」的项目说明和备注，直接用了第 5 步的编辑器。
- 计划外加了两个只给开发和测试用的环境变量：`VIBE_ATLAS_DATA_DIR`（换数据目录）和 `VIBE_ATLAS_SMOKE_REPORT`（冒烟测试模式）。
- 队列快捷键在计划的基础上多了 `J K`（同 `↑ ↓`）和 `Ctrl+C`（没有选中文字时复制当前改进点）。

## 遗留和限制

| 项目 | 说明 |
|---|---|
| 常驻内存 | 没有测，之后补 |
| 代码签名 | 没有签名，SmartScreen 可能拦截，需要手动放行 |
| 编辑中的外部变化 | 备注或项目说明正在编辑时，别处对同一段文字的修改要重新打开才看得到（只有一个人用，同时编辑同一条的情况很少） |
| macOS | 不在本期，见 [docs/backlog.md](../../docs/backlog.md) |
| git | 没有提交；是否提交由用户决定 |
