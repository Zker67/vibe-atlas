# 项目阶段

状态：`[partial]`：已实现，检查通过，等用户在真实窗口验收

## 用户原话

> 项目也有状态，立项中、开发中、测试中、上线中、完结
> 你看看怎么添加最合适

讨论后确认（「按你的建议来」）：

- 叫「阶段」，和改进点的「状态」（待办 / 进行中 / 完成）分开。
- 已有项目升级后是「开发中」，新建的项目默认「立项中」。
- 侧栏把「完结」的项目收进底部可折叠的「已完结 N」分组，顺带做掉 backlog 里的「项目归档」。
- 只记当前阶段和切换时间，不记完整历史。

## 目标与范围

项目有五个阶段：立项中、开发中、测试中、上线中、完结。用户手动切换，可以跳着切；软件不按改进点推断。

| 位置 | 做法 |
|---|---|
| 项目栏 | 项目名右边一个阶段色的小标签（阶段图标和名称，窄时只留图标），点开下拉切换（主入口） |
| 侧栏 | 没完结的照常按用户排序；收起成窄栏时悬停提示里写阶段（展开时不加悬停提示，免得移动鼠标时到处弹）。完结的收进底部「已完结 N」分组，可折叠，折叠状态记在本机；折叠时打开着的完结项目仍显示在分组标题下面。两组各自拖动排序 |
| 侧栏角标（后加） | 用户问「这个地方能显示和优雅的表达项目状态吗」：没完结的项目图标右下角加阶段角标，悬停（窄栏里是行的提示）说阶段和天数，完结的不加 |
| 右键菜单、项目菜单 | 「阶段 ▸」子菜单 |
| 新建 / 编辑项目弹窗 | 一行阶段选择 |
| 项目总览 | 项目说明卡片右上角「开发中 · 已 12 天」，悬停显示切换时间（后来由 [2026-11-18-projects-board](../2026-11-18-projects-board/00-overview.md) 的「阶段历程」卡片取代，去掉了这一处） |
| 「移到其他项目」、快速记录小窗 | 完结的排在最后、变淡，照样能选、能搜 |
| 切换组织 | 没有上次打开的项目时，打开第一个没完结的 |

## 不变量

- 人工驱动：阶段只由用户切换，不限制任何改进点操作。
- 记录要快：快速记录小窗只多一次排序，不多读任何东西。
- 已有数据不丢：升级只加列。

## 实施清单

1. `internal/store/store.go`：迁移 7（结构版本 8）：`projects.stage`（`planning` / `developing` / `testing` / `live` / `finished`，默认 `developing`）和 `stage_at`（升级时取 `created_at`）。
2. `internal/store/projects.go`：`Project.Stage`、`Project.StageAt`；`ProjectDraft.Stage`（新建为空时是 `planning`，编辑为空时不改）；`SetProjectStage(id, stage)`，阶段没变时不动时间。
3. `atlas.go`：绑定 `SetProjectStage`；`bun run generate`。
4. 前端：`src/lib/labels.ts` 阶段表；`src/state/atlas.ts` 的 `setProjectStage`、`projectToOpen` 跳过完结；项目栏、侧栏、弹窗、总览、四处「移到其他项目」、快速记录小窗。
5. 文档：`docs/product.md`、`docs/api.md`、`docs/backlog.md`（项目归档并入）、`internal/store/README.md`、使用说明。

## 验收

- 自动：store 测试 `TestProjectStage`（新建默认立项中、草稿指定、切换记时间、相同阶段不动、非法值报错、编辑留空不改）、`TestOpenUpgradesVersion7`（老项目变成开发中，`stage_at` 是创建时间）；`CGO_ENABLED=0 go vet ./...`、`CGO_ENABLED=0 go test ./...`、`bun run typecheck`、`bun run lint`、`bun run build`。
- 用户：在真实窗口里看项目栏的阶段标签和下拉、侧栏的「已完结」分组（折叠、展开、拖动排序、收起成窄栏时）、右键菜单、编辑弹窗、总览右上角、「移到其他项目」和快速记录小窗里完结项目的位置。

## 回滚

迁移只加列：回滚代码后旧版本会因为结构版本更高拒绝打开数据文件，需要先用备份的数据文件或保留新版本。
